# Figure 1 需求文档 — TestVDB 方法总览图

> 需求方:论文写作方。设计师:作者本人。本文档只约定**图必须让读者获得什么**,不约定画法。

## 1. 这张图是什么

论文的方法总览图(hero figure),对应 §3 Approach。读者在精读正文之前扫一眼这张图,就应该能独立拼出 TestVDB 的方法故事。它将同时接受两类检查:审稿人的"30 秒理解测试",和 R2 已书面提出的结构核查(见 §5 验收标准)。

## 2. 受众与阅读场景

- **受众**:FSE 审稿人(软件测试/数据库方向专家,熟悉 oracle、fuzzing、LLM 术语,但第一次见到本系统)
- **场景**:PDF 单栏渲染,约 17cm 宽;先图后文;多数读者会先看图决定要不要细读 §3
- **印刷**:必须黑白打印后仍完全可读(颜色只能作辅助编码,不能承载关键语义)

## 3. 信息需求(按读者认知顺序分级)

### R1 第一眼(3 秒):系统的形状
| # | 需求 | 理由 |
|---|------|------|
| R1.1 | 一眼看出**四阶段串行管线**的结构与顺序 | 论文所有叙事围绕"四阶段"组织,图是它的唯一视觉陈述 |
| R1.2 | 看出系统的**输入是自然语言 API 文档**、**产出是缺陷判定** | 头尾即"从什么到什么",读者定位问题域 |
| R1.3 | 看出**每个阶段由 LLM agent 驱动、执行与判定分离**的自动化性质 | 这是 "LLM pipeline" 的定性,与手工分析划清界限 |

### R2 第二眼(30 秒):每个阶段做什么
| # | 需求 | 理由 |
|---|------|------|
| R2.1 | 阶段①传达:文档被结构化为**约束**,且带类型/证据分级/来源核验的标记 | 支撑 §3.2 的"纪律化提取"主张;审稿人会核对 spec 质量控制是否在图中有踪迹 |
| R2.2 | 阶段②传达:策略是**预绑定**的(不是 LLM 现场自选),且存在生成侧质量闸门 | 支撑可审计性主张;5 gates 是生成侧唯一质控,缺失会显得生成裸奔 |
| R2.3 | 阶段③传达:在**固定版本的沙箱**里执行,留下原始 HTTP 日志 | 支撑可复现性;原始日志是后续证据链的原料,须在图中可见 |
| R2.4 | 阶段④传达:**装配证据与裁决是两个分离的角色**(evidence builder 与 chain auditor),中间经五节证据链 | **R2 5.3 明确批评现图缺失此点**;builder/auditor 分离是论文对抗 LLM 自参考的核心设计 |
| R2.5 | 阶段④传达:裁决前的**四视角交叉质询存在**(A contract / B physical / C cognition / D source) | 四视角是方法命名的机制,图中无名=方法不可验证 |
| R2.6 | 阶段④传达:**裁决有界重试**(rebuild 回环、次数有限)与**不确定即转人工**(Neutral → human) | 支撑"不强行判定"的诚实设计叙事;审稿人对 LLM judge 的第一质疑就是"会不会硬判" |

### R3 细看(1 分钟):论文主张的视觉锚
| # | 需求 | 理由 |
|---|------|------|
| R3.1 | **implementation source 与 API documentation 呈现为两条相互独立的信息源**,前者汇入判定、后者产生规格 | **全文最重要的单个视觉主张**:证伪锚独立于规格来源,打破"LLM 既出题又判卷"的自参考循环。R2 5.3 批评现图恰是此点缺失 |
| R3.2 | R3.1 的独立性在黑白打印下仍可辨(如线条样式/位置对位,而非仅颜色) | 见 §2 印刷约束 |
| R3.3 | 全程 artifact 流可见:knowledge.json → specifications.json → logs → evidence_chain.json | 支撑"每步可追溯"主张;审稿人复现意愿依赖此链完整 |
| R3.4 | (可选)DP:一句 running example(#10369)贯穿提示 | 若加入不得挤压 R1-R3 任何一条;正文已详述,删减无伤 |

## 4. 约束

| # | 约束 |

## 5. 验收标准(画完自查)

- [ ] **V1 遮文测试**:只看图+caption,一位未读正文的同行能正确回答:输入是什么;四阶段各一句话职责;为什么判定阶段可信(source 独立);最终产出是什么
- [ ] **V2 审稿核查**:R2 review 5.3 的三条(builder/auditor 分离、四视角、source 独立输入)在图中均可指出
- [ ] **V3 黑白测试**:灰度打印后,R3.1 的双源独立性与主要数据流仍可辨
- [ ] **V4 密度测试**:无任何一个元素需要说明文字以外的前置知识才能理解;无空洞装饰元素
- [ ] **V5 一致性测试**:图中术语 grep 正文均可命中,无同义漂移

## 6. 明确不需要

- 各阶段的实现细节(具体脚本数、agent 数、prompt 设计)——正文 §3 的职责
- 评测数字(51/81 等)——属于 §4
- 装饰性图标、渐变、无信息量的底纹
