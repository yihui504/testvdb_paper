# 中文 AI 风格检测模式

四层框架：词汇 -> 句法 -> 论证 -> 研究者视角。

---

## 评分体系

对修改后的文本进行 5 维评估（各 1-10 分，满分 50）：

| 维度 | 1-3 分 | 4-6 分 | 7-10 分 |
|------|--------|--------|---------|
| **直接性** | 大量铺垫、套话 | 偶有冗余 | 每句话都有信息增量 |
| **节奏变化** | 句长/段长几乎一致 | 有变化但不自然 | 长短自然交替，符合内容需要 |
| **读者信任** | 空话连篇、无数据支撑 | 偶有具体化 | 断言有数据、有出处、有限定 |
| **真实感** | 全正面、无困难、无权衡 | 偶提限制 | 有权衡、有失败、有作者立场 |
| **简洁度** | 删除20%+不影响含义 | 偶有冗余 | 每个词都有存在理由 |

目标：修改后总分 ≥ 35 分。

## Layer 1：词汇级

### 1.1 Tier 1 — 必须替换

| 禁用 | 替换方式 |
|------|----------|
| 深度融合 | 说明具体融合了什么、如何融合 |
| 赋能 | 说明具体提供了什么能力 |
| 协同 | 说明具体协作机制 |
| 多维度 | 列出具体维度名称 |
| 全方位 | 列出具体方面 |
| 高质量发展 | 说明具体指标变化 |
| 具有重要意义 | 说明具体意义是什么 |
| 提供了新的视角 | 说明视角新在哪里 |
| 填补了空白 | 引用文献证明确实无人研究 |
| 具有深远影响 | 说明影响的具体方面和范围 |
| 开创性地提出 | 直接陈述观点 |
| 至关重要 | 说明重要的具体原因 |
| 深入探讨/深入分析 | 直接分析，不用"深入" |
| 不仅如此 | 删除，直接写下一点 |
| 标志着 | 说明具体标志了什么变化 |
| 日益增长/日益凸显 | 用具体数字/事件说明 |
| 应运而生 | 删除，直接说出出现了什么 |
| 毋庸置疑 | 删除，或用数据证明 |

### 1.2 Tier 2 — 同段2+个时标记

| 词 | 替换 |
|----|------|
| 显著提升/显著改善 | 用具体数字："提升了23%" |
| 有效地 | 说明具体效果 |
| 创新性地 | 直接描述做了什么 |
| 系统性地 | 说明具体步骤 |
| 科学合理 | 给出合理的依据 |
| 此外 | 控制频率，同页不超过1次 |
| 然而 | 控制频率，同页不超过2次 |
| 因此/故而 | 控制频率，优先用因果句式代替 |
| 总之/概而言之 | 仅允许在全文结尾使用一次 |

### 1.3 空洞连接词

删除或改写，不保留：
- 值得注意的是
- 由此可见
- 不难发现
- 综上所述（仅允许在全文结论使用一次）
- 换言之
- 毋庸置疑
- 众所周知
- 不言而喻

### 1.4 模板开头

直接切入主题：

| 禁用 | 处理 |
|------|------|
| 随着……的深入发展 | 删除，直接写核心事实 |
| 在……背景下 | 仅在确需交代背景时保留，限一句 |
| 近年来，……引起了广泛关注 | 改为具体数据或事件 |
| 党的二十大报告指出（与主题无直接关系时） | 删除或移至脚注 |

## Layer 2：句法级

### 2.1 破折号过多

每页超过2个——或—— -> 改为逗号或拆分句子。

### 2.2 序号并列段落

第一……第二……第三……连续3段以上 -> 合并为连贯论述，仅在确需列举时使用。

### 2.3 强行总结句

每段末尾"因此/由此可见/综上" -> 删除总结句，让论证自然收束。

### 2.4 冒号列举伪论证

"主要表现在以下几个方面：" + 列举 -> 改为带分析的段落论述。

### 2.5 套话开头

每章以背景铺垫开头 -> 直接进入本章核心问题。

### 2.6 夸大收尾

每章以"意义重大"结尾 -> 改为对本章发现的客观小结。

### 2.7 重复指代

反复出现"该理论""该方法""该模式" -> 用具体名称代替，或使用代词。

### 2.8 维度并列

"从X维度、Y维度、Z维度分别分析" -> 按逻辑关系组织，不必强行分维度。

### 2.9 机械对仗

"既要……又要……""一方面……另一方面……"连续出现 -> 减少使用频率，改为自然句式。

### 2.10 硬过渡

| 禁用 | 处理 |
|------|------|
| 上一章探讨了……，本章将…… | 删除，直接开始本章内容 |
| 在前文分析的基础上 | 删除 |
| 基于以上论述 | 删除或仅在结论章使用 |

### 2.11 同义词轮换

同一概念在相邻段落用不同称呼 -> 统一术语。

### 2.12 段落等长

连续5段以上字数相近（±20字） -> 按内容需要调整段落长度。

### 2.13 三项并列

列举默认给三项 -> 按实际情况给出真实数量。

### 2.14 过度格式化

- 每个要点都**加粗** -> 仅对关键术语加粗，不超过每段1处
- 用 emoji 做标题/列表符号 -> 学术写作禁用 emoji
- 大量使用无序列表代替段落论述 -> 改为连贯段落

### 2.15 被动语态堆叠

连续3句以上"被……""受到……影响""得到了……" -> 改为主动语态，明确动作主体。

## Layer 3：论证级 — 最重要的层

### 3.1 缺少权衡（最大的 AI 特征）

AI：
> 本方法提高了准确率和效率。

研究者：
> 准确率的提升以额外的推理开销为代价（表4）。在样本量小于1000的数据集上，开销超过收益。

**检测**：断言改进但未提及成本、条件或限制的句子。
**修改**：加入一项——代价、条件、边界、或比较限定词。

### 3.2 无条件断言

AI：
> 方法A优于方法B。

研究者：
> 方法A在五个数据集中的四个上准确率更高，但在训练数据稀疏时差距缩小至1.2个百分点（图3b）。

**检测**：没有条件、例外或范围的绝对断言。
**修改**：加入条件、范围或数据引用。

### 3.3 全正面结果

AI：
> 结果表明本方法在所有设置下均有效。

研究者：
> 该方法在结构化数据上表现良好，但在自由文本输入上性能下降。我们推测这与§3.2中描述的分词不匹配有关。

**检测**：结果部分没有负面发现、没有边缘情况。
**修改**：差距最小的在哪里？最困难的是什么？失败模式是什么？

### 3.4 泛泛的局限性

AI：
> 本工作的一个局限性是可扩展性。未来的工作将解决这个问题。

研究者：
> 轨迹收集随执行长度线性增长，500步轨迹需要40分钟。并行化可以缩短时间，但需要重新设计状态合并协议（§5.1）。

**检测**：适用于任何论文的通用局限性。
**修改**：每项局限必须**具体**（什么问题）、**量化**（多严重）、**分析**（为什么）。

### 3.5 罗列式文献综述

AI：
> 张三（2023）提出了X方法。李四（2024）将其扩展到Y。我们的工作与他们的不同之处在于Z。

研究者：
> 张三（2023）解决了X问题，但假设了固定的词汇表，这在我们开放式场景中不适用。李四（2024）放宽了这一假设，但引入了3倍的延迟。我们的方法通过……避免了这两个问题。

**检测**：仅列举文献而不进行真正比较。
**修改**：对每篇引文——优点是什么、不适用于你的场景的是什么、你的方法为何不同。

### 3.6 对称比较

AI 对正反面给予同等权重，骑墙观望。

- AI："一方面是X，另一方面是Y。"
- 研究者："X是主要问题；Y在实践中影响较小，因为……"

**检测**：频繁的"一方面……另一方面……"或对称的利弊列表。
**修改**：表明立场。真正的研究者有观点。

## Layer 4：研究者视角

### 4.1 确定 -> 不确定

| AI确定式 | 研究者表述 |
|---------|-----------|
| 结果表明 | 结果初步表明 / 结果显示 |
| 证明了 | 支持了 / 为……提供了证据 |
| 证实了 | 与……一致 |
| 揭示了 | 似乎表明 |

**规则**：仅对形式可证的命题（定理、证明）使用"证明了"。实验结果 -> "表明"、"显示"、"初步支持"。

### 4.2 失败与意外

真实论文包含：
- "出乎意料的是，X并未改善Y"
- "与我们的预期相反，更简单的基线方法表现更好"
- "我们最初尝试了X，但发现……"
- "在……时出现了意外的性能下降"
- "这个结果的获得并非trivial，因为……"

**检测**：论文中没有任何意外/失败/困难的语言。
**修改**：找到2-3处结果出乎意料或初始尝试失败的地方。

### 4.3 研究者常用词汇

AI 几乎不用但研究者常用的词：

| 类别 | 词汇 |
|------|------|
| 诚实的困难 | 出乎意料、意外地、非平凡的、不稳定、困难、棘手、脆弱 |
| 谦逊的结果 | 有限的、边际的、渐进的、微小的、部分的 |
| 真实的不确定 | 我们假设、一种可能的解释是、目前尚不清楚、我们推测 |
| 过程描述 | 我们最初尝试了、经过多次迭代、关键的insight是、我们注意到 |
| 负面表述 | 未能改善、失败、性能退化、不成立、崩溃 |

### 4.4 设计决策理由

- AI："我们使用6层Transformer编码器。"
- 研究者："我们选择了6层，因为更深的模型在我们的数据集上出现过拟合（附录B）。CNN基线无法捕捉长距离依赖。"

**检测**：设计选择没有理由。
**修改**：对关键决策——为什么这个选择，考虑了什么替代方案。

### 4.5 具体的未来工作

- AI："未来的工作将关注可扩展性和泛化能力。"
- 研究者："一个待解决的挑战是将轨迹收集扩展到长horizon任务（>1000步）。基于检查点的采样是一个有前景的方向，但会牺牲完整性来换取效率。"

**检测**：足够通用、可以放在任何论文里的未来工作。
**修改**：与本文发现直接相关，技术上具体，对困难诚实。

### 4.6 Rebuttal 语气

| AI Rebuttal | 强 Rebuttal |
|------------|-------------|
| "感谢审稿人提出的宝贵意见。" | "审稿人提出了关于轨迹质量的重要问题。"（直入主题） |
| "我们同意可扩展性很重要。" | "为量化可扩展性问题，我们在三个额外的工作负载上测量了运行时间……" |
| "我们将在终稿中增加更多实验。" | "我们已运行了建议的实验。在数据集X上，性能降至Y%，证实Z是瓶颈。" |

**规则**：
1. 直入问题，不先感谢
2. 带数字
3. 展示已做的事，不做承诺
4. 审稿人说对了就承认
5. 用证据反驳，不用修辞
