# Stage 3: Refine / 打磨

## 目的
对完整论文做质量检查，并调整到符合页数限制。

## 前置条件
- Stage 2 完成（各节写完、论文可编译）
- `.self_xept/project.yml` 可用（页数限制等）

## 工作流

### Part A: 质量检查

#### Step 1: 通读全文
按顺序读完整篇论文，检查：

**内容质量:**
- [ ] 章节间叙事逻辑连贯
- [ ] 跨章节无矛盾
- [ ] 所有图表都被正文引用**且**被讨论
- [ ] 无断裂引用（`[?]`）或引用（`??`）
- [ ] 主张有充分支撑（引用或数据）

**一致性:**
- [ ] 术语全程一致（不为关键概念混用同义词）
- [ ] 缩写首次定义、之后一致使用
- [ ] 节内时态一致
- [ ] 你的方法/系统命名一致

**写作质量:**
- [ ] 对全文跑 post-write 自检清单（见 Stage 2）
- [ ] 无过长段落（>8 句）
- [ ] 无单句段落
- [ ] 章节过渡平滑

**格式:**
- [ ] 模板符合 venue 要求
- [ ] 匿名化正确（若 double-blind）
- [ ] 参考文献格式符合 venue 风格

#### Step 2: 修问题
优先级：
1. **致命** — 会导致拒稿（断裂引用、缺章节、超页数）
2. **重大** — 显著削弱论文（不一致、无支撑主张）
3. **次要** — 打磨（措辞、过渡）

修完所有问题，`pwsh` 跑 `latexmk` 重新编译。

---

### Part B: 篇幅控制

#### Step 1: 查当前页数
编译后比对实际页数 vs `.self_xept/project.yml` 的目标。

| 情况 | 动作 |
|------|------|
| 在限内 | 完成 → 进入最终编译 |
| 超 2-5 行 | 找孤行，逐处压缩 |
| 超半页 | 缩一张图 + 压孤行 |
| 超整页 | 次要内容移附录 |
| 少 >2 页 | 加深度（误差分析、案例、讨论） |

#### Step 2: 削减策略（超限时）
**优先从靠后章节削** — 前部内容审稿人看得更仔细。

**零成本削减（不丢内容）:**

| 冗长 | 简洁 |
|------|------|
| "In order to" | "To" |
| "It is worth noting that" | （删） |
| "a total of N" | "N" |
| "the method that uses X" | "the method using X" |
| "conduct an analysis of" | "analyze" |

**排版修正:**
- 两张小图 → 并排：`width=0.48\linewidth`
- 宽表 → `\resizebox{\columnwidth}{!}{...}` 或 `\small`
- 长 caption → 只留必要信息

**内容裁剪（最后手段）:**
- 次要实验移附录
- 合并相似 related work 条目
- 删一个次要 ablation/分析变体

**找孤行:**
- 找末行只有 2-5 词的段落
- 收紧措辞把那行拉上来 → 省一整行
- 逐栏检查此模式

#### Step 3: 扩展策略（不足时）
**加价值，不加废话:**
- 误差分析 / 失败案例
- 具体案例或示例
- 延伸讨论影响
- 补充 related work 覆盖
- 架构或工作流图

#### Step 4: 迭代
每轮调整后重新编译，重复直到页数达标。

---

### Part C: 最终编译
1. `pwsh` 跑 `latexmk` 最后一次
2. 验证：
   - [ ] 页数达标
   - [ ] 无编译错误（检查日志无 `! ` 错误行）
   - [ ] PDF 渲染正确
   - [ ] 无页面留 >1/4 空白
   - [ ] 无孤行/寡行
   - [ ] 图表靠近首次引用处
3. 向用户报告任务完成

## 输出
- 打磨并优化页数后的论文
- 干净编译（日志零错误）
- 最终 PDF
