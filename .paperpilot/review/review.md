## Reviewer 1: Domain Expert

**Overall Recommendation:** Weak Accept

### Summary
TestVDB addresses the reliability gap in Vector Database Management Systems (VDBMSs) by targeting API compliance defects — bugs where a VDBMS silently accepts inputs or produces behaviors that violate its documented contract. The paper presents the first LLM-driven system for detecting these defects, introducing Contract-Truth Separation (CTS) to address a novel failure mode: contract hallucination propagation, where an LLM both generates a contract and judges compliance, leading to self-confirmed false positives. The core contribution is a dev-reviewer agent that falsifies LLM-generated assertions against maintainer-authority evidence (source grounding, clean reproduction, by-design intent) via three counter-evidence anchors. Evaluated on five VDBMSs, TestVDB submitted 111 candidate issues; maintainers acknowledged 36 (28 fixed, 8 accepted), achieving 69.2% end-to-end precision — a 5.4× improvement over the 12.9% single-layer LLM-judgment baseline. The system honestly bounds its scope: it specializes in boundary/validation compliance (75% of yield), is complementary to crash-focused fuzzing (VDBFuzz), and does not solve soft result-correctness oracles (ANN recall, ranking).

### Core Strengths
- **S1:** First LLM-driven system for API compliance defects in VDBMSs — see 2.1, 4.1, 4.2
- **S2:** Contract-Truth Separation principle addresses the contract-hallucination propagation problem — see 3.3, 4
- **S3:** Empirical validation at scale (111 issues, 36 acknowledged across 5 VDBMSs) — see 4.1, Table 3
- **S4:** Honest boundary setting (complementary to VDBFuzz, does not solve result-correctness oracles) — see 1, 4.1
- **S5:** Three-anchor dev-reviewer design with empirical complementarity evidence — see 3.3, 4.3

### Core Weaknesses
- **W1:** Threat-model evaluation is exploratory and inconclusive (small n, unstable dev-reviewer) — see 4.4
- **W2:** Controlled retrospective is pilot-scale (12 candidates); full 52-candidate re-triage pending — see 4.3
- **W3:** TP-recall limitation of dev-reviewer (20–60%) not fully characterized — see 4.4
- **W4:** Literature cache provisional [SSL/rate-limit blocked full-text fetch] — see background.md

### Detailed Assessment
1. **Significance** — Adequate
   - **1.1** The problem is significant and timely. 43% of VDBMS bugs are incorrect-behavior defects — a majority class crash oracles cannot detect. The scope is bounded but meaningful: API compliance defects are a tractable slice, and the paper does not overclaim. [provisional]
   - **1.2 [minor, fixable]** Significance would be strengthened by explicit discussion of deployment practicality (automated issue filing → maintainer triage → acknowledgement may not scale to CI without discussion).
2. **Novelty** — Adequate
   - **2.1** CTS — isolating LLM assertions from a truth layer — is, to my knowledge, the first systematic characterization and mitigation of contract hallucination propagation in LLM-driven testing. Observed in 12 by-design cases. [provisional]
   - **2.2** Clear delta against cited competitors: VDBFuzz (crash only), NoREC/DDLCheck (SQL semantics), roadmap (agenda, no system). Related Work positions these accurately. [provisional]
   - **2.3 [minor, fixable]** Could position more explicitly against broader LLM-driven testing beyond multi-agent debate.
3. **Soundness** — Adequate
   - **3.1** Core claims supported: RQ3 ablation (12.9% → 69.2%, 5.4×) is sound; dev-reviewer removes 80.6% FP.
   - **3.2 [major, fixable]** RQ4 threat-model pilot inconclusive (blindspot indicators unpopulated, dev-reviewer unstable, n=5) — component empirically unvalidated.
   - **3.3 [minor, fixable]** Controlled retrospective is pilot-scale (12); directional but statistically thin; full 52 pending.
   - **3.4 [minor, fixable]** TP-recall 20–60% reported honestly but net utility not characterized.
4. **Verifiability** — Adequate
   - **4.1** Five-stage pipeline + 3-anchor CTS described with enough detail to follow.
   - **4.2 [minor, fixable]** No artifact link despite "open-source system" claim.
5. **Presentation** — Excellent
   - **5.1** Well-structured, readable, logical narrative.
   - **5.2 [minor, fixable]** Minor notation: Table 3 column "acknowledged" vs formula denominator — add a brief legend.

### Questions for Authors
- **Q1:** Artifact link (GitHub/Zenodo) for the "open-source system" claim? — moves 4.2 to Excellent.
- **Q2:** Any preliminary results from the full 52-candidate re-triage to substantiate the threat-model's effect? — addresses 3.2.
- **Q3:** Characterize net utility of 20–60% TP recall given base candidate volume? — clarifies 3.4.

## Reviewer 2: Area Specialist

### Summary

The paper observes that 43% of VDBMS bugs are incorrect-behavior defects (vs 23% crash/hang), yet fuzzers like VDBFuzz rely on crash oracles.
