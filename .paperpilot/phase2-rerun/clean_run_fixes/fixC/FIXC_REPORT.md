## 3. 核心发现：规则显式化 ≠ 执行稳定化

**显式化的 E1-E5 消解次序没有产生收敛**（κ 中位 0.030，与 r3 甚至负相关）。方差根源不在
"reviewer 不知道优先级"，而在**规则适用条件判定的执行漂移**：

1. **E2 需要主动跨通道对照动作——执行与否随会话**：milvus_035（Int64 字符串强转）的 fixC
   会话未实际对比 gRPC 行为 → 落入 E5 兜底 → 对照劣化；而 milvus_038/039/042 的会话执行了
   E2 对照（判词明写 "gRPC rejects"）→ 翻对。同一规则、同一现象类，命运取决于会话是否做了
   那个动作。
2. **E3 命中与否取决于 Grep 深度**：能否找到 errIgnored* 意图常量/注释决定幂等类走向（找到 →
   FP 对向；找不到 → 契约压倒 → 错向）——取证深度的轮方差直接成为裁决轮方差。
3. **对错 21/32 ≈ r1 持平**：即使规则部分执行，方向上无净损失也无收益。

**论文表述**（RQ2 机制层）：*结构化 rubric 可以规定证据层级的名义次序，但不能稳定其执行——
LLM judge 的 run-to-run 方差位于"规则适用条件的判定"（是否做了对照、是否找到常量、契约断言
存在与否），而非规则本身的缺失。显式化（fixC）与锚点注入（fixA）的对照证明：能稳定执行的
干预只有把裁决方向预编译进材料的锚点（fixA 10:3），而要求运行时判定的规则无论写得多显式
都保持概率性。*

## 4. 与既有结论的整合

- fixA（材料侧锚点）：有效但受三条件约束（现象类普适、无 GT 方向冲突）。

  由锚点三条件（纪律 §9）数学限定——灰区（GT 态度分裂）对三者全部封闭。
