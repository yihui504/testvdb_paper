# Analyze Files（分析素材文件）

用独立子代理分析文件。文件内容**不**进你的上下文——子代理读并提取关键信息，存到 `.self_xept/references.md`，然后结束。

## 何时用
- 用户要求分析、读、总结或对比**任意文件**
- 用户新上传文件（PDF、论文、数据集、代码）
- 任何需读大文档的任务

**文件分析总用本技能**，即便单文件。防止大文件内容填满上下文。

## 工作流

### Step 1: 查已有分析
`read` `.self_xept/references.md`（## Literature Index）看哪些文件已分析过。除非用户要求重分析，跳过这些。

### Step 2: 分析文件
对每个文件，用 **subagent 工具派发一个独立子代理**：
- 传入：文件路径、提取任务（如"提取核心想法、方法、关键结果、局限"）
- 子代理用 `read` 读文件（隔离上下文）
- 子代理提取：基本信息、关键内容、用户指定细节、任何有用信息
- 子代理把分析结果 `write`/`edit` 追加到 `.self_xept/references.md`（## Literature Index，含索引条目）
- 子代理返回简短确认给你（不含全文）

### Step 3: 综合
所有文件分析完后：
1. `read` `.self_xept/references.md` 取分析
2. 综合并向用户呈现结果

## 提取什么
对每个文件，子代理应捕获：

**论文（PDF、preprint）**：
- 核心想法 / 论点
- 方法 / 路径
- 关键结果 / 发现
- 局限
- 用户指定细节（若有）

**数据文件（CSV、数据集）**：
- 描述与结构
- 关键统计
- 在项目里怎么用

**代码文件**：
- 用途与关键算法
- 与论文的关系

**其他文件**：
- 描述与关键内容
- 与项目的相关性

## 要点
- **无上下文污染**：文件内容留在子代理，不进你的对话
- **单一缓冲**：所有分析进 `.self_xept/references.md`（统一知识库）
- **去重**：重分析同文件就地更新
- **重分析**：换不同提取任务时重新派发子代理即可
- **顺序**：一次分析一个文件，保持干净
