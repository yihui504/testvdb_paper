# Ideation 评估框架

5 维评分量表（每维 1-5 档）。每维需 1-2 句 justification 引用量表档位。

---

## 维度一：Novelty（原创性）

相对已有工作的原创程度。

| 分档 | 描述 |
|-----|------|
| 1/5 | 已有方法的直接复制或微小变种 |
| 2/5 | 对已知方法的渐进式改进，无新洞察 |
| 3/5 | 现有技术的全新组合或应用到新领域 |
| 4/5 | 文献未见的重要新视角、新形式化或新方法 |
| 5/5 | 开辟新研究方向的突破性想法或根本性问题重构 |

**示例 justification**（软件工程/机器学习领域）：
- "3/5 — 将对比学习应用于日志异常检测是该领域新应用，但对比学习本身已成熟。AIOps 领域无同类工作。"
- "4/5 — 提出用因果推断替代相关性分析来定位性能瓶颈，该方法在分布式系统调试中未见。"

---

## 维度二：Feasibility（可行性）

资源范围内能否实现并评估？

| 分档 | 描述 |
|-----|------|
| 1/5 | 需要不可得的数据/算力/专业知识 |
| 2/5 | 原则可行但面临重大阻碍（稀有数据集、专用硬件） |
| 3/5 | 中等努力可实现；部分组件需额外准备或学习 |
| 4/5 | 完全在可达范围内，使用现有工具/数据/专业知识 |
| 5/5 | 使用现有基础设施和文档完备的方法，可直接实现 |

**示例 justification**：
- "4/5 — 使用公开基准（GLUE/SuperGLUE）和标准 Transformer 架构，单 GPU 足够训练。唯一风险是数据预处理时间。"
- "3/5 — 需访问企业级 CI/CD 历史数据，可通过开源项目数据集替代；实现需学习现有测试优先级工具的 API。"

---

## 维度三：Impact（影响力）

对目标社区的潜在贡献。

| 分档 | 描述 |
|-----|------|
| 1/5 | 不会被注意或引用；解决非问题 |
| 2/5 | 仅小众兴趣；相关于小范围子社区 |
| 3/5 | 有用贡献，领域从业者会注意 |
| 4/5 | 解决广泛认知的问题；可能吸引广泛关注 |
| 5/5 | 解决重大开放问题或显著推动后续研究 |

**示例 justification**：
- "4/5 — 代码生成中的 LLM 幻觉是广泛关注问题。实用的缓解方法会同时吸引 NLP 和软件工程社区注意。"
- "3/5 — 针对微服务架构的特定资源调度优化，对云服务开发者有用但受众限于 DevOps 子领域。"

---

## 维度四：Research Gap（研究空白）

填补文献空白的程度。

| 分档 | 描述 |
|-----|------|
| 1/5 | 无空白；该领域已充分覆盖 |
| 2/5 | 空白微小或已被同期工作部分解决 |
| 3/5 | 明确存在空白但较窄；相关工作已暗示方向 |
| 4/5 | 已识别空白且无满意现有方案 |
| 5/5 | 多篇综述明确指出的关键空白 |

**示例 justification**：
- "3/5 — 虽然 prompt 优化已充分研究，但多目标 prompt 调优（平衡精度与延迟）探索有限。2-3 篇近期论文涉及但未提供完整框架。"
- "4/5 — 针对 GraphQL N+1 查询的自动检测在工业界有强需求，但现有文献仅集中于 REST API，迁移路径未明确。"

---

## 维度五：Clarity（清晰度）

此阶段想法的定义清晰度。

| 分档 | 描述 |
|-----|------|
| 1/5 | 模糊概念，无具体问题/方法/评估计划 |
| 2/5 | 大致方向已定，关键组件未定义 |
| 3/5 | 问题清晰；方法已勾勒但评估标准缺失 |
| 4/5 | 问题/方法/评估策略表达清晰，有少量空白 |
| 5/5 | 完全明确：清晰的问题、方法、假设、指标、预期结果 |

**示例 justification**：
- "4/5 — 低资源语言的知识图谱完成问题和方法（带图神经网络的跨语言迁移）已清晰。评估指标（MRR, Hits@10）已指定，但数据集选择需细化。"
- "3/5 — 提出'基于 LLM 的代码审查自动化'方向明确，但未明确评估基线（人工审查 vs 工具对比）和指标（准确率/召回率定义）。"

---

## 评分指南

- **每项分数必须包含 1-2 句 justification**，引用量表档位
- Justification 应提及具体证据（论文、数据集、资源）
- 各维度分数可大范围波动 — 这是预期且有益的
- Novelty 高但 Feasibility 低是有效结果（在风险评估中标记）

---

> **借鉴来源**：本框架参考 PaperPilot 的 ideation 评估框架，针对 xept 领域（软件工程/机器学习/系统）调整示例，保持结构一致。
