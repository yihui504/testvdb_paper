# Software Engineering Review Criteria

## Evaluation Dimensions
### 1. Novelty (Weight: 25%): Novel problem/approach/insight? Clear differentiation from prior work? Significance explained? Scoring: 1-5
### 2. Soundness/Rigor (Weight: 30%): Methodology clearly described? Design decisions justified? Appropriate research method? Threats to validity discussed? Statistical tests appropriate? Scoring: 1-5
### 3. Verifiability/Reproducibility (Weight: 25%): Replication package available? Data available? Implementation details sufficient? Setup reproducible? Scoring: 1-5
### 4. Presentation (Weight: 20%): Clear writing? Logical structure? Figures/tables clear? Appropriate length? Scoring: 1-5

## Required Sections (SE Papers)
1. Abstract / 2. Introduction / 3. Background/Motivation / 4. Approach/Method / 5. Evaluation / 6. Threats to Validity / 7. Related Work / 8. Conclusion

## Common Issues
**Major**: Missing/weak threats to validity, inadequate baselines, overclaiming, no replication package
**Minor**: Related work too brief, unclear RQs, missing implementation details, poor figure quality

## Paper Types
### Tool Paper: Focus on usefulness, usability, real-world evaluation. Must have: user study or deployment evidence.
### Empirical Study: Focus on methodology rigor, statistical validity. Must have: clear RQs, appropriate tests, threats.
### Survey Paper: Focus on comprehensiveness, systematic methodology. Must have: clear scope, search methodology, synthesis.
