# Content Analysis Guide - Software Engineering

## Purpose
Extract and organize key information from research materials. Understanding and structuring — not summarizing.

## What to Extract
### 1. Research Context: Background, Motivation, Challenge
### 2. Contribution: Key Contribution, Novelty, Key Insight (the "aha" moment)
### 3. Technical Details
**Methodology**: Overall approach/architecture, key algorithms/techniques, implementation details (language, LOC, frameworks), design decisions/rationale
**Evaluation**: Research Questions (RQ1, RQ2...), datasets/benchmarks, baselines, metrics, key results
### 4. Metadata: Target venue, page limit, paper type

## SE Conventions
1. Quantify claims — "50% improvement" not "significant improvement"
2. Precise terminology — use correct technical terms
3. Threats awareness — note potential validity threats
4. Reproducibility — note what's needed for replication
5. Distinguish clearly — "our approach" vs "existing approaches"

## Confidence-Aware Language
| Confidence | Language Style | Example |
|------------|----------------|---------|
| High | Direct, specific | "achieves 2.3x speedup" |
| Medium | Moderate hedging | "demonstrates improved performance" |
| Low | Strong hedging | "shows promising results" |
