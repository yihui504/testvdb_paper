# RQ2 判据包 · 质量门控（草案 v1，2026-09-11）

用途：**issue 逆推重建的包，必须先逐门通过本表，才可作为 RQ2 判据输入。**
每个门的「当前违反」是对现有 81 个包的实测值，用来校准重建的工作量。

---

## G1 · 版本一致

**要求**：包内每条契约行的来源版本 == 该包的受测版本。禁止用 vendor 级固定版本契约补全。

**机械校验**：解析每行 `source_url` 的版本片段，与包表头 `version=` 比对；不一致即不过。

**当前违反**：**299 行**（族 1–5；成因是 `augment_contracts.py` 硬编码每 vendor 一份契约）。
**8 个包无本版来源**：weaviate 1.37.4 ×4（本版契约仅 1 行可检索内容）、qdrant 1.12.1 ×1、qdrant 1.18.1 ×2、milvus 2.3 ×1。

## G2 · 引用可解析

**要求**：`source_url` 是可访问 URL，目标页面存在且是对应端点/参数的页。

**机械校验**：HTTP 可达 + 非重定向死链 + 非站点落地页（页面须含该行的参数或断言语义）。

**当前违反**：死链 1 条（`v2.3.x/.../Query.md` → 301 `/docs`）、不可解析 1 条（`milvus.io/docs/index.md`）、**落地页 27 条**（引 `api-reference` 根页，页面无任何端点文档）。

## G3 · 引用类型标注

**要求**：每条契约行标明来源类型 —— 文档 / 结构化 spec / 实现源码。**不得把源码锚或 spec 锚当作文档锚呈现。**

**机械校验**：按 URL 域名与路径分类，与行内声明比对。

**当前违反**：**weaviate 51/54 与 47/47 锚在仓库内 OpenAPI `schema.json`**；milvus 版本契约有本地路径（`.milvus-src-2617/...`）与散句描述充当 `source_url`。qdrarnt/milvus 其余多为文档域名。

> ⚠ **这一门牵动论文论证**：Table 1 第 5 行把 OpenAPI 派生划入"达不到 system-level untagged prose"之列，而 Weaviate 的约束恰来自 OpenAPI schema。**先标注、后论证** —— 是否构成对前提的冲击，需与论文一起定，不在门控内自动判定。

## G4 · 端点相关

**要求**：契约行的 `endpoint` 与候选 `endpoint` 匹配。注入行的选择口径必须是端点，不是参数名。

**机械校验**：规范化 endpoint 并求交。

**当前违反**：**456/929（49.1%）补充契约行与候选端点无关**；66/79 个包至少含 1 条。
（dispatch 模板自己写着"若契约条目与候选 endpoint 无关，忽略之" —— 等于让评委忽略掉近一半的契约材料。）

## G5 · 观察证据非空

**要求**：`--- 观察到的行为（observed） ---` 段非退化。

**当前违反**：1 包（`milvus_001`，53 字符，明写"无可用观察记录"）。
其余 80 包中位 2,375 字符 —— 本维健康。

## G6 · 无候选锚定泄漏

**要求**：材料任何位置不得出现本候选的 issue 号、维护者裁决，或把结论写进说明性文字。

**机械校验**：正则扫 issue 号 / 裁决词，并**逐条看上下文**（维护者态度段是论文认可的材料，不算违反）。

**当前违反**：**4 包**在「补充契约依据（文档考古补全）」段的 `_provenance` 字段写入 issue 号 **并复述缺陷**：

| 包 | `_provenance` 内容（节选） |
|---|---|
| milvus_008 | issue #49059; cosine similarity [-1,1] / distance = 1 - similarity |
| milvus_013 | issue #49890 — … **float 3.5 silently truncated, string "abc" silently ignored** |
| milvus_038 | issue #52311 — … **vector-field group_by silently accepted** |
| qdrant_016 | issue #9522 — … **non-existent ref silently returns 200** |

**待确认**：这 4 个 issue 是否为该候选**自己**的 issue（需候选→issue 映射）。若成立，即为对"盲评"的直接解盲通道。

## G7 · 审计留痕

**要求**：每包产出各门通过记录（G1–G6 逐项结果 + 证据），随包归档，可复核。

## G8 · 包内不得预置来源侧分析

**要求**：包只装「观察到的行为」+「文档契约依据」两类材料。**实现源码分析、来源侧核查结论一律不得进包** —— 那是确认阶段（evidence builder / chain auditor）的工作，预置进包等于把结论递给评委。

**由来**：milvus_013 试点中发现。该案查到实现侧事实（`timeout_middleware.go:183` 的 ParseInt 回退语义），它解释了观察、但不属于"期望"侧证据，故写入审计记录而非重建包。

## 重建规格（走 issue 逆推）

1. **契约行来源**：每个候选只取**它自己受测版本**的契约/文档（G1）。
2. **缺口处置**（8 包）：weaviate 1.37.4 ×4 —— 需从 1.37.4 的 OpenAPI 或文档补契约；qdrant 1.12.1/1.18.1 ×3、milvus 2.3 ×1 —— 需补抽取或另行取证。**方式仍可是逆推**（从 issue 与文档反推），但产物必须过门。
3. **选择口径改为端点**（G4），参数匹配可作为补充维度但不得替代。
4. **`_provenance` 只留来源信息**（文档快照/URL），不留 issue 号与行为描述（G6）。
5. **来源类型标注**（G3）。
6. **落地页引用**一律补到具体端点页（G2）。
