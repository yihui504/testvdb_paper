### Current Behavior

Milvus v2.6.10 accepts field names that violate documented naming rules (numeric prefixes, special characters, hyphens), and more critically, **the stored data becomes inaccessible** - users cannot query these fields after insertion.

### Expected Behavior

Field names should be validated according to the documented naming rules:
- Must start with a letter or underscore
- Can only contain letters, numbers, and underscores

Example expected error during INSERT:
```
<ParamError: (code=1100, message=Invalid field name '123field': field name must start with a letter or underscore)>
```

### Documentation Evidence

According to the official [Milvus Limits Documentation](https://milvus.io/docs/limitations.md):

> **Resource Naming Rules:**
> 
> | Resource | Limit |
> |----------|-------|
> | Collection | 255 characters |
> | Field | 255 characters |
> | Index | 255 characters |
> | Partition | 255 characters |
>
> **The name of a resource such the collection name, partition name, or index name can contain numbers, letters, and underscores (_). A resource name must start with a letter or an underscore (_).**

**Source URL:** https://milvus.io/docs/limitations.md

**Quote:**
> "The name of a resource such the collection name, partition name, or index name can contain numbers, letters, and underscores (_). A resource name must start with a letter or an underscore (_)."

**Evidence Analysis:**
- Field is listed as a resource type with a 255 character limit
- The naming rule explicitly applies to "resource names"
- Field names should follow the same naming convention as collection names, partition names, and index names
- The rule clearly states: **"must start with a letter or an underscore (_)"**

### Impact

- **Data Loss Risk**: Users may believe data is stored, but it becomes inaccessible
- **Schema Inconsistency**: May lead to inconsistent schema design
- **Client Compatibility**: May cause issues with field name parsing in client libraries
- **Documentation Violation**: Actual behavior contradicts documented requirements
- **Cross-System Integration**: May cause problems when integrating with other systems

### Severity

**P1 (High)** - This bug causes data inaccessibility. Users can insert data but cannot retrieve it, leading to potential data loss.

### Root Cause

The dynamic schema feature in Milvus is not properly validating field names when they are added through data insertion. The validation exists at query time (which is why queries fail), but is missing at insert time.

### Suggested Fix

1. **Add Validation at Insert Time**:
   - Apply the same naming rules to field names as collection names
   - Validate field names during dynamic field creation
   - Return clear error message if validation fails

2. **Validation Rules**:
   - Must start with a letter (a-z, A-Z) or underscore (_)
   - Can only contain letters, numbers, and underscores
   - Maximum length: 255 characters

3. **Error Message**:
   ```
   <ParamError: (code=1100, message=Invalid field name '123field': 
   field name must start with a letter or underscore, and can only 
   contain letters, numbers, and underscores)>
   ```
