### Current Behavior

Milvus v2.6.10 accepts `ef=0` when searching with HNSW indexes (HNSW, HNSW_PQ, HNSW_SQ, HNSW_PRQ), which violates the documented requirement that `ef` must be a positive integer (> 0).

### Expected Behavior

Search should fail with a clear error message indicating that `ef` must be a positive integer greater than 0.

Example expected error:
```
<ParamError: (code=1100, message=Invalid search parameter 'ef': value must be greater than 0, but got 0)>
```

### Steps To Reproduce

```markdown
1. Create a collection with vector field
2. Insert test data into collection
3. Create an HNSW index with valid parameters
4. Attempt to search with `ef=0`
5. Observe that search succeeds (should fail)


from pymilvus import MilvusClient

client = MilvusClient(uri="http://localhost:19530")
collection_name = "test_hnsw_ef_0"

# Create collection and index
client.create_collection(
    collection_name=collection_name,
    dimension=128,
    metric_type="L2"
)
client.insert(collection_name=collection_name, data=[{"vector": [0.1]*128, "id": 1}])

# Create HNSW index with valid parameters
from pymilvus.milvus_client.index import IndexParams
index_params = IndexParams()
index_params.add_index(
    field_name="vector",
    index_type="HNSW",
    metric_type="L2",
    params={"M": 16, "efConstruction": 100}
)
client.create_index(collection_name=collection_name, index_params=index_params)

# Try to search with ef=0 (invalid)
res = client.search(
    collection_name=collection_name,
    data=[[0.1]*128],
    limit=10,
    search_params={"ef": 0}
)
```

### Contract Violation

1. **Parameter Validation Contract**: According to [Milvus HNSW Index Documentation](https://milvus.io/docs/hnsw.md), `ef` parameter must be a positive integer for HNSW indexes.

### Impact

- **Incorrect Search Behavior**: Searching with `ef=0` may lead to undefined search results or performance issues
- **User Confusion**: Users may perform searches with invalid parameters without realizing the parameter is invalid
- **Documentation Violation**: Actual behavior contradicts documented requirements

### Severity

**P1 (High)** - This is a critical parameter validation issue that affects all users searching with HNSW indexes. While it doesn't cause crashes, it allows execution of potentially invalid search operations.

### Suggested Fix

1. **Add Parameter Validation**:
   - Validate `ef` parameter before executing search
   - Ensure `ef >= 1`
   - Return clear error message if validation fails

2. **Improve Error Messages**:
   - Identify specific parameter name ("ef")
   - Specify expected valid range (e.g., "must be a positive integer")
   - Provide actual invalid value that was provided
