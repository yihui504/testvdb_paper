### Current Behavior

`POST /v2/vectordb/entities/search` returns HTTP 200 for all invalid parameter values, placing error information only in the JSON body.

#### 1. limit (topK) boundary values

| limit | HTTP | code | Message |
|-------|------|------|---------|
| 0 | 200 | 65535 | "topk [0] is invalid, should be in range [1, 16384]" |
| -1 | 200 | 65535 | "topk [-1] is invalid" |
| -100 | 200 | 65535 | "topk [-100] is invalid" |

```bash
curl -s -X POST 'http://localhost:19530/v2/vectordb/entities/search' \
  -H 'Content-Type: application/json' \
  -d '{"collectionName":"test","data":[[1,2,3,4]],"limit":0}'
# HTTP 200 / {"code":65535,"message":"topk [0] is invalid..."}
```

#### 2. Vector dimension mismatch (collection dim=4)

| Vector dim | HTTP | code | Message |
|-----------|------|------|---------|
| 64 | 200 | 1801 | "dimension: 4, but length of []float: 64" |
| 128 | 200 | 1801 | "dimension: 4, but length of []float: 128" |
| 2 | 200 | 1801 | "dimension: 4, but length of []float: 2" |

**Note**: Earlier versions (pre-v2.6) reported "length of []float: 0" regardless of actual input length, which was a misleading secondary bug. This has been fixed in v2.6.17 — the error message now correctly reports the actual vector length. However, the HTTP 200 status code issue remains.


### Expected Behavior


1. `limit=0` / `limit=-1` → `HTTP 400 / {"code":400,"message":"limit must be >= 1, got X"}`
2. Dimension mismatch → `HTTP 400 / {"code":400,"message":"vector dimension X does not match collection dimension 4"}`

### Steps To Reproduce

```markdown
import requests

BASE = "http://localhost:19530"
HEADERS = {"Content-Type": "application/json"}

# Bug 1: limit boundary
for lim in [0, -1, -100]:
    r = requests.post(f"{BASE}/v2/vectordb/entities/search", json={
        "collectionName": "test", "data": [[1.0,2.0,3.0,4.0]],
        "limit": lim
    }, headers=HEADERS)
    print(f"limit={lim}: HTTP {r.status_code} code={r.json()['code']}")

# Bug 2: dimension mismatch (collection has dim=4)
for dim in [64, 128, 2]:
    r = requests.post(f"{BASE}/v2/vectordb/entities/search", json={
        "collectionName": "test", "data": [[0.5]*dim], "limit": 3
    }, headers=HEADERS)
    print(f"vector_dim={dim}: HTTP {r.status_code} code={r.json()['code']}")
```

### Impact

- **limit=0**: Common frontend pagination bug. Should clearly reject, not return 200
- **limit=-1**: Integer overflow/unsigned conversion risk
- **Dimension mismatch**: Returns HTTP 200 instead of 400, preventing middleware detection
- **HTTP 200 prevents middleware detection**: Load balancers, API gateways, and monitoring tools can't distinguish errors from successes
