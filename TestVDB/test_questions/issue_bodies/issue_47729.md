### Current Behavior

Milvus v2.6.10 accepts `nprobe=0` when searching with IVF indexes (IVF_FLAT, IVF_PQ, IVF_SQ8, SCANN, BIN_IVF_FLAT), which violates the documented requirement that `nprobe` must be a positive integer (> 0).

### Expected Behavior

Search should fail with a clear error message indicating that `nprobe` must be a positive integer greater than 0.

Example expected error:
```
<ParamError: (code=1100, message=Invalid search parameter 'nprobe': value must be greater than 0, but got 0)>
```

### Contract Violation

1. **Parameter Validation Contract**: According to [Milvus Index Documentation](https://milvus.io/docs/index.md), `nprobe` parameter must be a positive integer for IVF indexes.

2. **Documentation References**:
   - [Milvus Index Documentation](https://milvus.io/docs/index.md) - Official documentation for index parameters
   - `nprobe` is a search parameter for IVF indexes (IVF_FLAT, IVF_PQ, IVF_SQ8, SCANN)
   - Parameter definition: "nprobe: Number of cluster units to search... Must be a positive integer."
   - Multiple technical articles and community resources confirm this parameter requirement

### Impact

- **Incorrect Search Behavior**: Searching with `nprobe=0` may lead to undefined search results or performance issues
- **User Confusion**: Users may perform searches with invalid parameters without realizing the parameter is invalid
- **Documentation Violation**: Actual behavior contradicts documented requirements

### Suggested Fix

1. **Add Parameter Validation**:
   - Validate `nprobe` parameter before executing search
   - Ensure `nprobe >= 1`
   - Return clear error message if validation fails

2. **Improve Error Messages**:
   - Identify specific parameter name ("nprobe")
   - Specify expected valid range (e.g., "must be between 1 and nlist")
   - Provide actual invalid value that was provided
