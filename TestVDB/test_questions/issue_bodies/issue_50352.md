### Current Behavior

The `POST /v2/vectordb/collections/create` endpoint has **multiple parameter validation gaps** across dimension, metricType, and consistencyLevel. All invalid inputs return HTTP 200 instead of HTTP 4xx.

#### 1. dimension boundary values accepted with HTTP 200

| Test Value | HTTP Status | JSON code | Message |
|-----------|------------|-----------|---------|
| dimension=0 | **200** | 1100 | "dimension is required..." (misleading: treats 0 as missing) |
| dimension=-1 | **200** | 65535 | "should be in range 2 ~ 32768" |
| dimension=32769 | **200** | 65535 | "should be in range 2 ~ 32768" |

Documented valid range: 1 ~ 32768

```bash
curl -s -X POST 'http://localhost:19530/v2/vectordb/collections/create' \
  -H 'Content-Type: application/json' \
  -d '{"collectionName":"test_dim_0","dimension":0,"metricType":"COSINE"}'
# HTTP 200 / {"code":1100,"message":"dimension is required..."}
```

#### 2. metricType enum violations accepted with HTTP 200

| Test Value | HTTP Status | JSON code | Behavior |
|-----------|------------|-----------|----------|
| `""` (empty) | **200** | **200** | ✅ Silently accepted as valid |
| `"INVALID"` | **200** | 1100 | Error in body but HTTP 200 |
| `"l2"` (lowercase) | **200** | 1100 | Error in body but HTTP 200 |
| `"123"` | **200** | 1100 | Error in body but HTTP 200 |

Documented valid values: L2, IP, COSINE

```bash
curl -s -X POST 'http://localhost:19530/v2/vectordb/collections/create' \
  -H 'Content-Type: application/json' \
  -d '{"collectionName":"test_mt_empty","dimension":4,"metricType":""}'
# HTTP 200 / {"code":200,"data":{}}   ← Empty metricType accepted!
```

#### 3. consistencyLevel enum violations silently accepted

| Test Value | HTTP Status | JSON code | Behavior |
|-----------|------------|-----------|----------|
| `""` (empty) | **200** | **200** | ✅ Silently accepted |
| `"STRONG"` (uppercase) | **200** | **200** | ✅ Silently accepted |
| `"strong"` (lowercase) | **200** | **200** | ✅ Silently accepted |
| `"None"` | **200** | **200** | ✅ Non-existent level accepted |
| `"ReadCommitted"` | **200** | **200** | ✅ Non-existent level accepted |

Documented valid values: Strong, Session, Bounded, Eventually

```bash
curl -s -X POST 'http://localhost:19530/v2/vectordb/collections/create' \
  -H 'Content-Type: application/json' \
  -d '{"collectionName":"test_cl_none","dimension":4,"metricType":"L2","consistencyLevel":"None"}'
# HTTP 200 / {"code":200,"data":{}}   ← "None" is not a valid consistency level!
```


### Expected Behavior

All invalid parameter values should be rejected with HTTP 400 and appropriate error messages:

1. **dimension**: Values outside [1, 32768] → `HTTP 400, code=400, message="dimension must be in range [1, 32768], got X"`
2. **metricType**: Values not in {L2, IP, COSINE} → `HTTP 400, code=400, message="invalid metricType 'X', must be L2, IP, or COSINE"`
3. **consistencyLevel**: Values not in {Strong, Session, Bounded, Eventually} → `HTTP 400, code=400, message="invalid consistencyLevel 'X'"`


### Steps To Reproduce

```markdown
import requests

BASE = "http://localhost:19530"
HEADERS = {"Content-Type": "application/json"}

# Bug 1: dimension boundary
for dim in [0, -1, 32769]:
    r = requests.post(f"{BASE}/v2/vectordb/collections/create", json={
        "collectionName": f"test_dim_{dim}", "dimension": dim, "metricType": "COSINE"
    }, headers=HEADERS)
    print(f"dimension={dim}: HTTP {r.status_code}, code={r.json()['code']}")

# Bug 2: metricType enum
for mt in ["", "INVALID", "l2", "123"]:
    r = requests.post(f"{BASE}/v2/vectordb/collections/create", json={
        "collectionName": f"test_mt_{mt[:8]}", "dimension": 4, "metricType": mt
    }, headers=HEADERS)
    body = r.json()
    is_ok = body.get("code") == 200
    print(f"metricType='{mt}': {'OK' if is_ok else 'ERR'} HTTP {r.status_code} code={body['code']}")

# Bug 3: consistencyLevel enum
for cl in ["", "STRONG", "strong", "None", "ReadCommitted"]:
    r = requests.post(f"{BASE}/v2/vectordb/collections/create", json={
        "collectionName": f"test_cl_{cl[:8]}", "dimension": 4,
        "metricType": "L2", "consistencyLevel": cl
    }, headers=HEADERS)
    body = r.json()
    is_ok = body.get("code") == 200
    print(f"consistencyLevel='{cl}': {'OK' if is_ok else 'ERR'} HTTP {r.status_code} code={body['code']}")
```

### Impact

1. **Empty metricType creates collections with undefined similarity behavior** — indexing and search may silently fail
2. **Case-insensitive consistencyLevel** means users who set "STRONG" thinking they get strong consistency actually get whatever default behavior exists (case mismatch silently treated as valid)
3. **Non-existent consistency levels** ("ReadCommitted", "None") are silently accepted, misleading users about actual consistency guarantees
4. **API contract violations across dimension, metricType, and consistencyLevel** — three independent validation gaps on the most critical creation endpoint

  - Documents valid values: Strong, Session, Bounded, Eventually — "None" and "ReadCommitted" are not valid

  - Documents valid metric types: L2, IP, COSINE — empty string is not a valid metric type


- This is part of a systematic REST API v2 validation pattern (see also #25521, #50018, #49889)
- Discovered through automated boundary value testing on v2.6.17
- The collections/create endpoint is the most critical entry point — validation gaps here propagate to all downstream operations
- Note: While `dimension=-1` and `dimension=32769` DO get error codes (65535) in the JSON body, the HTTP 200 status is still incorrect
- The empty-string cases for metricType and consistencyLevel are the most dangerous because they return code=200 (success) with no error indication anywhere
