### Current Behavior

The Milvus v2 REST API accepts empty strings (`""`) for the `dbName` parameter across multiple endpoints. The official documentation defines `dbName` as "The name of an **existing** database" — an empty string is not a valid database name, yet the API returns `code: 0` (success) with no validation error.

This is the same category of bug as #49844 (filter null/missing accepted), which has been `triage/accepted`.

**Empty dbName on collections/list:**
```bash
curl -s -X POST 'http://localhost:19530/v2/vectordb/collections/list' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer root:Milvus' \
  -d '{"dbName": ""}'
```
Response: `{"code":0,"data":[]}` — success, silently defaults to the default database.

**Empty dbName on collections/describe:**
```bash
curl -s -X POST 'http://localhost:19530/v2/vectordb/collections/describe' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer root:Milvus' \
  -d '{"collectionName": "test_collection", "dbName": ""}'
```
Response: `{"code":0,"data":{...}}` — success, no validation error for empty dbName.

**Empty dbName on collections/drop:**
```bash
curl -s -X POST 'http://localhost:19530/v2/vectordb/collections/drop' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer root:Milvus' \
  -d '{"collectionName": "test_collection", "dbName": ""}'
```
Response: `{"code":0}` — success, no validation error for empty dbName.

For comparison, `filter=""` is now correctly rejected in v2.6.16:
```bash
curl -s -X POST 'http://localhost:19530/v2/vectordb/entities/query' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer root:Milvus' \
  -d '{"collectionName": "test_collection", "filter": ""}'
```
Response: `{"code":100,"message":"invalid parameter: filter cannot be empty"}` — correctly rejected.

### Expected Behavior

Return a non-zero code with an error message indicating that `dbName` must be a valid database name, consistent with how `filter=""` is now rejected (code=100) and `limit=0` is rejected (code=65535):

```json
{"code": 65535, "message": "invalid parameter: dbName must be a valid database name, got empty string"}
```

### Steps To Reproduce

1. Start Milvus v2.6.16 standalone (Docker)
2. Send a request with `dbName: ""` to any endpoint that accepts `dbName`:
   ```bash
   curl -s -X POST 'http://localhost:19530/v2/vectordb/collections/list' \
     -H 'Content-Type: application/json' \
     -H 'Authorization: Bearer root:Milvus' \
     -d '{"dbName": ""}'
   ```
3. Observe that the response is `{"code":0,"data":[]}` — no validation error

### Milvus Log

No error or warning is logged when `dbName=""` is used. The request is processed silently:

```
[GIN] [/v2/vectordb/collections/list] [code=200] [latency=1.234ms] [method=POST] [error=]
```

### Anything else?

- This bug was discovered through automated parameter validation testing.
- The official [List Collections](https://milvus.io/api-reference/restful/v2.4.x/v2/Collection%20(v2)/List.md) documentation defines `dbName` as "The name of an existing database." An empty string is not an existing database name.
- The same `dbName` parameter appears in [Create Collection](https://milvus.io/api-reference/restful/v2.4.x/v2/Collection%20(v2)/Create.md), [Describe Collection](https://milvus.io/api-reference/restful/v2.4.x/v2/Collection%20(v2)/Describe.md), and other endpoints — all with the same definition.
- This is the same category of issue as #49844 (filter null/missing accepted) and #49823 (nprobe=0 accepted) — REST API v2 parameter validation gaps.
- `filter=""` has been fixed in v2.6.16 (returns code=100), but `dbName=""` remains unfixed. Both are empty string values for parameters that should require non-empty values.
